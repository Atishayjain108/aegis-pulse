# AEGIS-LLM-0002 — Provider Timeout

## Summary
A provider call exceeded its hard timeout budget (`AEGIS_LLM_TIMEOUT_S`, default 120s).

## Diagnosis
```bash
# Check which provider is slow
aegis llm health

# Test completion time manually
time aegis llm complete "ping" --provider ollama
```

## Resolution
- Increase `AEGIS_LLM_TIMEOUT_S=180` in `.env` for large model responses.
- Switch to a faster model: `AEGIS_OLLAMA_MODEL=llama3.2:3b`.
- Check system resources: `htop` — is the CPU/RAM maxed out?
- If Ollama is swapping to disk: your model is too large for available RAM.
  Use a quantised version: `ollama pull qwen2.5:7b-instruct-q4_K_M`.

# AEGIS-LLM-0003 — Output Blocked by Guardrail

## Summary
The LLM output was blocked by a guardrail rule (PII, toxic content, or length).

## Diagnosis
```bash
# Check logs for which rule fired
# Look for: guardrail.block rule=... snippet=...
```

## Resolution
- **PII detected**: Review prompt — are you passing user data that is reflected in output?
  Add a PII scrubber step before sending to LLM.
- **Toxic content**: The model hallucinated harmful content. Use a higher-quality model.
- **Output too long**: Reduce `max_tokens` or break the task into smaller steps.
- **False positive**: If the guardrail is too aggressive, use `skip_guardrails=True`
  on specific calls (eval/debug only — never in production).

# AEGIS-LLM-0004 — Structured Output Parse Failure

## Summary
`InstructorAdapter` could not parse the LLM output into the target pydantic schema
after all retries.

## Diagnosis
```bash
# Run with DEBUG logging to see the raw output:
AEGIS_LOG_LEVEL=debug aegis llm complete "your prompt"
```

## Resolution
1. Lower temperature: `AEGIS_LLM_TEMPERATURE=0.0` for structured output.
2. Add explicit JSON examples to your prompt.
3. Use a more capable model (e.g. switch from `llama3.2:3b` to `qwen2.5:14b`).
4. Simplify your pydantic schema — fewer fields, simpler types.
5. Increase `max_retries` in `InstructorAdapter(max_retries=3)`.

# AEGIS-LLM-0005 — Circuit Breaker Open

## Summary
A provider's circuit breaker tripped due to a high error rate (>30% over 60s).

## Resolution
- The circuit will automatically half-open after 120 seconds.
- To force recovery: restart the provider service.
- Check provider-specific logs for the root cause.
- If Ollama: `systemctl --user restart ollama` (or kill + restart `ollama serve`).

# AEGIS-LLM-0006 — Invalid Prompt Template

## Summary
A Jinja2 prompt template failed validation (missing front-matter, missing required vars, etc.)

## Diagnosis
```bash
# List loaded templates
aegis llm eval --golden-dir /dev/null  # just triggers registry load + log output
```

## Resolution
- Ensure every `.jinja2` file has a YAML front-matter block between `---` delimiters.
- Check `required_vars` list matches the variables you pass to `registry.render()`.
- Validate Jinja2 syntax: `python -c "from jinja2 import Template; Template(open('your.jinja2').read())"`

# AEGIS-LLM-0007 — Embedding Failed

## Summary
The embedding pipeline (Ollama bge-m3 or sentence-transformers) returned an error.

## Resolution
```bash
# Check bge-m3 is pulled
ollama list | grep bge-m3

# If missing:
ollama pull bge-m3

# Test embed directly
aegis llm embed "test sentence"
```

# AEGIS-LLM-0008 — Semantic Router Failed

## Summary
The `SemanticRouter` failed to embed the query for route classification.

## Resolution
- This is usually caused by the same issue as AEGIS-LLM-0007 (embed failure).
- The gateway will fall through to normal LLM completion — no data loss.
- Fix the embedding service to restore the fast-path.

# AEGIS-LLM-0010 — Context Too Long

## Summary
The rendered prompt exceeds the provider's context window limit.

## Resolution
1. Reduce the number of signals passed to the agent (use `--limit`).
2. Summarise signals before passing to LLM.
3. Switch to a model with a larger context:
   - Gemini 2.0 Flash: 1M tokens
   - Groq llama-3.3-70b: 131k tokens
4. Use `aegis analyze --limit 10` instead of `--limit 50`.
